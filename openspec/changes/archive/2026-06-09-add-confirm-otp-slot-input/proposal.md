## Why

The `/confirm` route asks the user to enter the 6-digit code that
Cognito sends after `/signup`, but the field is a single plain
`<Input placeholder="123456">`. On mobile the keyboard does not
reliably show the numeric pad, paste into a 6-character text
field is fiddly, and the field gives no visual cue that the
input is six discrete digits — the most common UX mistakes
(typing into the email field, missing the autocomplete one-time
code hint from iOS/Android, fat-fingering a digit and not
noticing) all stem from the field not looking like a code box.
Shadcn ships `input-otp` exactly for this case: six slots, paste
distribution across slots, automatic focus advance, and
keyboard/numeric-only enforcement out of the box.

The migration is tactical and isolated: one route file, one new
`components/ui/input-otp.tsx` primitive copied via the shadcn
CLI, and one Zod schema that already validates a 6-character
string. No backend, no API contract, no other routes.

## What Changes

- Install the shadcn `input-otp` primitive into
  `apps/web/src/components/ui/input-otp.tsx` (via `pnpm dlx
  shadcn@latest add input-otp`).
- Replace the `<Input>` that captures `code` in
  `apps/web/src/routes/confirm.tsx` with `<InputOTP
  maxLength={6}>` composed of six `<InputOTPSlot>`s (no
  separators), wired through the same RHF `Controller` so
  `confirmSchema` validation continues to fire on submit and
  on change.
- Keep `placeholder="123456"`-equivalent ergonomics by relying
  on the empty slots themselves as the visual hint; remove the
  now-redundant `placeholder` prop.
- Preserve `autoComplete="one-time-code"`, `inputMode="numeric"`,
  and `aria-invalid` on the underlying `<InputOTP>` so iOS/Android
  SMS-autofill and screen-reader behavior survive.
- All user-visible strings stay in Spanish (`Código de
  verificación`, error copy unchanged).

## Capabilities

### New Capabilities

- `auth-frontend-confirm`: Captures the contract of the
  `/confirm` route's verification-code field — what shape the
  input has, how the six-digit code is captured, how validation
  surfaces, and how SMS-autofill / paste interact with it. Future
  refinements (rate-limit messaging, code-expired hint, etc.)
  extend this capability rather than reopen it.

## Impact

- Affected code:
  - `apps/web/src/routes/confirm.tsx` — swap the `<Input>` block
    inside the `code` `Controller` render prop for an `<InputOTP>`
    composition.
  - `apps/web/src/components/ui/input-otp.tsx` — new file,
    generated by `pnpm dlx shadcn@latest add input-otp` (uses the
    `input-otp` npm package under the hood, which the shadcn
    generator adds to `apps/web/package.json`).
- Affected dependencies:
  - `apps/web/package.json` gains `input-otp` (peer of the shadcn
    primitive). `pnpm-lock.yaml` updates accordingly.
- Affected tests:
  - `apps/web/tests/unit/routes/confirm.test.tsx` (or equivalent)
    — assertions that target the single `<input
    name="code">` get rewritten to target six slot elements and
    a paste event that distributes the digits.
- Affected docs:
  - `docs/sprints/03-tenants-and-rls.md` — append a "Sprint
    follow-up — `/confirm` OTP slot input (sprint 3.7,
    2026-05-27)" section after the existing 3.6 follow-up,
    documenting motivation, change scope, and verifiable
    outcome.
- Not affected (out of scope for this change):
  - `/onboarding`, `/tenants/new`, `/signup`, `/login`,
    `/forgot-password`, `/reset-password`, `AuthLayout`,
    `useConfirmSignupMutation`, `useResendCodeMutation`,
    `confirmSchema`, the `Resend code` button, the email field
    in `/confirm`, the backend, and any other shadcn migration
    (form, select, calendar, sonner, tabs) — those land in
    separate changes after sprint 3.6 closes.
- No ADR: this is a tactical component swap inside the envelope
  already set by [ADR-0009 — Frontend
  stack](../../../docs/adr/0009-frontend-stack.md) (shadcn/ui is
  the chosen primitive library); picking a specific shadcn
  component is not an architectural decision.

## Carry-over (2026-05-30)

Blocked on mobile-device smoke (iOS Safari + Android Chrome confirming the SMS autofill chip fills all six OTP slots) and the merge PR. Frontend implementation is complete and covered by vitest.
