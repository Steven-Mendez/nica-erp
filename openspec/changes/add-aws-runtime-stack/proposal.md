## Why

`add-terraform-state-backend` provisions the persistent edge (state +
ECR + S3+CloudFront), `add-api-container-image` publishes the API
image, and `add-deploy-destroy-automation` wraps the operator
ergonomics — but none of those stands the application up. **This
change is where the API actually runs in AWS.** It declares every
ephemeral resource (VPC, RDS, ECS service, ALB, Cognito, SSM, base
observability) and composes them into a single `envs/demo/` root that
`terraform apply` brings up and `terraform destroy` tears down. After
this change ships, `https://<dist-id>.cloudfront.net/api/healthz`
returns `db:"ok"` plus the real Alembic revision, closing the
walking-skeleton loop end-to-end against real AWS.

The split exists because these resources together drive the bulk of
the monthly cost (NAT, RDS, ALB, Fargate) — they SHALL be cleanly
destroyable so that idle accounts return to ≈ $0/month
([ADR-0018](../../../docs/adr/0018-rolling-deploys.md)). Bundling them
into one change keeps the destroy/recreate symmetry obvious: every
resource declared here disappears together when `make destroy` runs.

## What Changes

- New Terraform module **`infra/terraform/modules/network/`**:
  - VPC `10.0.0.0/16`, two AZs, one public subnet + one private
    subnet per AZ.
  - One NAT Gateway in AZ-a (cost-optimised single NAT, not
    multi-AZ).
  - Internet gateway, route tables, default routes.
  - **Gateway** VPC endpoints for S3 and DynamoDB (free; reduce NAT
    traffic). No Interface endpoints
    ([`docs/10-infrastructure.md` §Excluded from initial tier](../../../docs/10-infrastructure.md#excluded-from-initial-tier)).
  - Security groups: `sg_alb` (ingress from the AWS-managed prefix
    list `com.amazonaws.global.cloudfront.origin-facing` only),
    `sg_ecs_tasks` (ingress from `sg_alb` on `:8000`), `sg_rds`
    (ingress from `sg_ecs_tasks` on `:5432`).
- New Terraform module **`infra/terraform/modules/data/`**:
  - RDS PostgreSQL 17, single-AZ, `db.t4g.micro`, gp3 20 GB,
    `skip_final_snapshot=true`, `deletion_protection=false`,
    `backup_retention_period=0`, `multi_az=false`,
    `performance_insights_enabled=false`
    ([ADR-0017](../../../docs/adr/0017-backups-pitr.md) — pre-launch
    accepts data loss on destroy).
  - DB credentials generated by Terraform `random_password`, stored
    in SSM SecureString under `/nica-erp/demo/rds/url`,
    `/nica-erp/demo/rds/username`, `/nica-erp/demo/rds/password`
    ([ADR-0021](../../../docs/adr/0021-ssm-parameter-store.md)).
  - Module flags `enable_rds_proxy=false`, `enable_read_replica=false`
    (declared as variables so later sprints can flip them without
    code changes).
- New Terraform module **`infra/terraform/modules/compute/`**:
  - ECS cluster `nica-erp-demo` (Fargate, no EC2 capacity providers).
  - Two task definitions sharing the same image
    (`${ecr_repository_url}:${image_tag}`):
    - `nica-erp-api` (long-running): CPU `256`, memory `512`, port
      `8000`, env vars `APP_ENV=aws`, `DATABASE_URL` and
      `ALEMBIC_DATABASE_URL` resolved from SSM at task launch,
      `GIT_SHA` inherited from the image, container logs streamed to
      CloudWatch Logs group `/nica-erp/api`.
    - `nica-erp-migrate` (one-off): identical container image and env
      vars, but overrides the `command` to
      `["alembic","upgrade","head"]`. ECS RunTask is the invocation
      path; the migration script in
      `add-deploy-destroy-automation` calls it.
  - ECS service `nica-erp-api` running the API task definition,
    `desired_count = 1`, attached to an ALB target group on port
    `8000`, deployment strategy `rolling` with min healthy `100%`
    and max healthy `200%`.
  - Application Load Balancer `nica-erp-demo-alb` listening on HTTP
    `:80` only (no ACM, no HTTPS listener
    [ADR-0020](../../../docs/adr/0020-no-custom-domain-mvp.md)),
    one default target group forwarding to the API service.
  - Target tracking auto-scaling policy on the API service
    (`TargetValue=50`,
    `PredefinedMetricType=ECSServiceAverageCPUUtilization`,
    `scale_in_cooldown=300`, `scale_out_cooldown=60`). Variables
    `api_min_capacity=1` and `api_max_capacity=1` (MVP default);
    raising `api_max_capacity` activates the policy with no further
    Terraform change
    ([`docs/10-infrastructure.md` §API auto-scaling](../../../docs/10-infrastructure.md#api-auto-scaling)).
- New Terraform module **`infra/terraform/modules/auth/`**:
  - Cognito User Pool Lite `nica-erp-demo` with the custom attribute
    `custom:active_tenant` (`String`, `Mutable=true`, empty by
    default). The attribute is declared on day one to avoid User Pool
    recreation when later sprints populate it
    ([sprint 03](../../../docs/sprints/03-tenants-and-rls.md)).
  - One app client `nica-erp-spa` (public client, no client secret),
    allowed OAuth flows: `code`, allowed OAuth scopes:
    `openid email profile`.
  - User pool domain with the default prefix
    `nica-erp.auth.us-east-1.amazoncognito.com` (no custom domain,
    [ADR-0020 §Cognito user pool domain](../../../docs/adr/0020-no-custom-domain-mvp.md#cognito-user-pool-domain)).
    Hosted UI is **not** used in the MVP; the domain only exists to
    expose the OAuth/JWKS endpoints.
- New Terraform module **`infra/terraform/modules/secrets/`**:
  - SSM SecureString parameters: `/nica-erp/demo/rds/url`,
    `/nica-erp/demo/rds/username`, `/nica-erp/demo/rds/password`,
    `/nica-erp/demo/cognito/user-pool-id`,
    `/nica-erp/demo/cognito/client-id`. KMS key alias
    `alias/aws/ssm`.
  - Placeholder SSM parameters declared but blank for
    `/nica-erp/demo/jwt/secret` — explicitly NOT used in AWS
    because Cognito-issued JWTs replace `LOCAL_JWT_SECRET`. Sprint
    02 fills it in if/when needed; sprint 01 leaves it empty.
- New Terraform module **`infra/terraform/modules/observability/`**:
  - CloudWatch Logs group `/nica-erp/api` with `retention_in_days=14`.
  - CloudWatch alarm `nica-erp-alb-5xx` on the ALB metric
    `HTTPCode_Target_5XX_Count`, threshold "more than 1% of total
    requests in any 5-minute window", treat missing data
    `notBreaching`.
  - CloudWatch alarm `nica-erp-rds-cpu` on the RDS metric
    `CPUUtilization`, threshold ">= 80% for 10 minutes".
  - SNS topic `nica-erp-alerts` with an email subscription pointing
    at `var.alert_email`. (Domain-specific alarms — sales latency,
    outbox lag — are added by their respective sprints.)
- New Terraform composition **`infra/terraform/envs/demo/`**:
  - `backend.tf` configures the S3 backend with
    `bucket=nica-erp-tf-state`, `dynamodb_table=nica-erp-tf-lock`,
    `key=envs/demo/terraform.tfstate`, `encrypt=true`.
  - `main.tf` composes the six modules above, wires module outputs
    into module inputs (network → compute SGs; data → SSM params;
    compute → ALB DNS → CloudFront origin update; auth → SSM
    params).
  - `terraform.tfvars.example` documents `aws_region`, `alert_email`,
    `image_tag` (defaults to the contents of `.deploy-image-tag` if
    present, otherwise required), `api_min_capacity`,
    `api_max_capacity`. The real `terraform.tfvars` is gitignored.
- **CloudFront origin swap** for the `/api/*` behavior declared in
  `add-terraform-state-backend`: an `aws_cloudfront_distribution`
  data source reads the bootstrap-created distribution, and a
  separate Terraform-managed resource updates the `api-placeholder`
  origin's `DomainName` to the freshly-created ALB DNS name. This
  uses `aws_cloudfront_distribution`'s `lifecycle.ignore_changes`
  hooks to avoid churn on attributes the bootstrap root still owns
  (default behavior, S3 origin, custom error responses). Design
  details in [design.md](design.md).

## Capabilities

### New Capabilities

- `aws-network`: VPC, subnets, NAT Gateway, security groups, and the
  gateway VPC endpoints that bound the ephemeral network surface.
- `aws-data`: the RDS PostgreSQL instance and its SSM-stored
  credentials, configured for pre-launch destruction safety
  (no PITR, no final snapshot, no proxy, no replica).
- `aws-compute`: the ECS cluster, both task definitions (API +
  migration), the API service, the ALB on HTTP `:80`, and the
  target-tracking auto-scaling policy.
- `aws-auth`: the Cognito User Pool with `custom:active_tenant`
  declared on day one, its public SPA app client, and the
  default-prefix user pool domain that exposes JWKS/OAuth endpoints.
- `aws-secrets`: SSM SecureString parameters that carry DB
  credentials and Cognito identifiers, with the placeholder for
  `LOCAL_JWT_SECRET` explicitly empty in AWS.
- `aws-observability`: the API CloudWatch Logs group, base ALB-5xx
  and RDS-CPU alarms, and the SNS alert topic the rest of the
  sprints subscribe domain alarms to.
- `aws-demo-environment`: the `envs/demo/` Terraform root that
  composes the six modules above and the `/api/*` CloudFront origin
  swap that closes the public URL loop.

### Modified Capabilities

- `web-static-hosting`: the `/api/*` behavior on the bootstrap-created
  CloudFront distribution SHALL transition from the
  `placeholder.invalid` origin (defined in `add-terraform-state-backend`)
  to the ALB DNS name created by this change. The behavior itself
  (path pattern, cache policy, origin-request policy, allowed
  methods) does not change.

## Impact

- Affected code: new `infra/terraform/modules/{network,data,compute,auth,secrets,observability}/`,
  new `infra/terraform/envs/demo/`, no changes to `apps/api/` or
  `apps/web/`.
- Affected APIs: introduces the publicly reachable HTTP surface
  `https://<dist-id>.cloudfront.net/api/healthz` (and any other
  `apps/api/` route under `/api/*`). No code-level API contract
  changes; the routes are the same ones served locally.
- Dependencies: requires `add-terraform-state-backend` (state
  backend, ECR repo, distribution placeholder) and
  `add-api-container-image` (a tag exists in ECR). Adds no new
  Python or Node dependencies.
- Systems: introduces every ephemeral AWS resource described in
  [`docs/10-infrastructure.md`](../../../docs/10-infrastructure.md)
  for the demo tier; idle hourly cost ≈ \$0.10/h (NAT + ALB + RDS +
  Fargate task). Designed to be destroyed nightly to honour the
  near-zero idle cost goal.
- Out of scope (intentionally): the migration RunTask wrapper
  (`scripts/run-migrations.sh`) and the destroy/verify automation
  — both `add-deploy-destroy-automation`. The `email/` module
  (sprint 02), `storage/` module (sprint 05), `workers/` module
  (sprints 06–08), `messaging/` module (sprint 07) — explicitly
  later. Hosted UI for Cognito, WAF, X-Ray, Interface VPC endpoints —
  excluded from the MVP tier
  ([`docs/10-infrastructure.md` §Excluded from initial tier](../../../docs/10-infrastructure.md#excluded-from-initial-tier)).
