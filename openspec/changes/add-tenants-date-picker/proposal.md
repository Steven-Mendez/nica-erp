## Why

Sprint 3.8 (`improve-tenants-new-form`) left the two DGI
validity dates (`valid_from`, `valid_to`) as bare `<Input
type="date">` because date pickers required a separate
primitive install (Calendar + Popover) and bigger UX
consideration. With sprint 3.8 landed, the `/tenants/new`
wizard now mixes shadcn Select / Checkbox / Tooltip with
native browser date inputs whose appearance differs across
Chrome, Safari, and Firefox, ignores the project's dark-mode
theme, and offers no Spanish month-name formatting.

The fix is the canonical shadcn date-picker pattern: a
`<Popover>` triggered by a `<Button>` that displays the
formatted date via `date-fns/format`, with a `<Calendar>`
inside the popover for selection.

## What Changes

- Install shadcn `calendar` and `popover` primitives via
  `pnpm dlx shadcn@latest add calendar popover`. This pulls
  `react-day-picker`, `date-fns`, and
  `@radix-ui/react-popover` into the workspace.
- Add a small reusable wrapper
  `apps/web/src/components/ui/date-picker.tsx` that wraps
  the Popover + Button + Calendar trio behind a controlled
  `value: string` (ISO `YYYY-MM-DD`) / `onChange: (iso:
  string) => void` API. Spanish month/day labels via
  `date-fns/locale/es`.
- Replace the two `<Input type="date">` blocks in
  `apps/web/src/routes/tenants/new.tsx`'s DGI step with the
  new `<DatePicker>` wrapper, wired through `Controller` so
  the existing Zod `regex(/^\d{4}-\d{2}-\d{2}$/)` validation
  still gates the field.
- Keep ISO `YYYY-MM-DD` as the on-wire format committed back
  to React Hook Form — the backend Pydantic schema parses
  ISO strings, and the existing `formatApiError` mapping
  for `authorization_dgi.valid_from` / `valid_to` keeps
  working.

## Impact

- Affected code:
  - `apps/web/src/components/ui/calendar.tsx`,
    `apps/web/src/components/ui/popover.tsx` — new files,
    generated by the shadcn CLI.
  - `apps/web/src/components/ui/date-picker.tsx` — new
    file: a small wrapper that owns the popover open
    state, ISO ↔ Date conversion, Spanish formatting, and
    forwards `value` / `onChange` to RHF `Controller`.
  - `apps/web/src/routes/tenants/new.tsx` — DGI step body:
    swap two `<Input type="date">` for `<DatePicker>` wired
    via `Controller`.
- Affected dependencies:
  - `apps/web/package.json` gains `react-day-picker`,
    `date-fns`, `@radix-ui/react-popover` (peer deps).
- Affected tests:
  - `apps/web/tests/unit/routes/tenants-new.test.tsx` —
    extend coverage: the DGI step renders two
    `<DatePicker>` buttons (one for valid_from, one for
    valid_to), clicking a button opens the calendar, and
    picking a date commits an ISO string to the form
    value.
- Affected docs:
  - `docs/sprints/03-tenants-and-rls.md` — append a
